# FlowScope 竞赛版计算原型（视觉草案）

这里是面向全国大学生数字媒体竞赛的独立前端视觉草案，不修改现有 `pipeline-energy-cloud` 后端，也不替代工程计算校核。最终计算路线以同目录的 `CALCULATION_DESIGN_OPTIONS.md` 和用户确认结果为准；当前三张页面里的浏览器演示公式不会直接作为正式工程算法。

## 与大创版的可审查差异

| 页面 | 大创版现状 | 竞赛版方案 | 差异类型 |
| --- | --- | --- | --- |
| 水利分析 | 单个稳态流量 → 摩阻、压头、末站压力 | `Q(t)` 波动场景 → 96 点压力包络、越限概率、安全裕度 | 输入从静态变为时间场景，输出从单值变为风险分布 |
| 敏感性分析 | 单因素 ± 百分比，平均敏感系数 | 多参数联合采样 → 秩相关全局贡献、样本云图、P95 风险 | 分析设计从局部导数/斜率变为全局不确定性传播 |
| 泵站优化 | 7 组固定泵数枚举，按末站压力最小选一组 | 连续转速决策 → 安全、能耗、启停磨损三目标 Pareto 前沿 | 决策变量、目标函数、输出结构均改变 |

## 接入正式后端前必须冻结的接口

这些页面目前使用浏览器内的可解释演示计算，便于展示交互和答辩。正式接入时建议新增独立接口，不要覆盖大创接口：

- `POST /competition/hydraulic-scenario`：输入基准流量、波动幅度、周期、温度和管线参数；输出时间序列压力包络、最低/最高压头、越限概率和风险点。
- `POST /competition/global-sensitivity`：输入变量分布、样本数和随机种子；输出全局贡献、交互贡献、P95/P5 风险和样本摘要。
- `POST /competition/pareto-optimization`：输入泵曲线、转速上下限、末站压力上下限、能耗/寿命权重；输出 Pareto 候选集、推荐折中点和约束解释。

## 重要说明

“与大创至少 50% 不同”不能仅凭页面颜色或代码行数证明。这里采用四个可答辩的差异维度：输入状态、决策变量、目标/评价函数、输出指标。正式提交前应对 Java 后端新增策略做同样的变更登记、单位测试和边界测试，并在论文中明确这是竞赛版模型，不声称替代原工程策略。
