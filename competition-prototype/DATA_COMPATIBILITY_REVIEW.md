# 竞赛计算路线与现有数据管理兼容性复核

## 现有数据管理能提供什么

### 项目 `t_project`

- 项目编号、名称、负责人、日期。

### 管道 `t_pipeline`

- 长度 `length`
- 外径 `diameter`
- 壁厚 `thickness`
- 设计年输量 `throughput`
- 起点/终点高程 `start_altitude`、`end_altitude`
- 粗糙度 `roughness`
- 年工作时间 `work_time`

### 泵站 `t_pump_station`

- 泵效率、电机效率
- 排量 `displacement`
- 进站压力/功率字段 `come_power`
- ZMI480、ZMI375 扬程

### 油品 `t_oil_property`

- 油品名称
- 密度
- 运动粘度

## 对之前三条路线的结论

| 路线 | 现有数据兼容性 | 结论 |
| --- | --- | --- |
| 瞬态压力波/水击 | 部分兼容 | 管长、直径、壁厚、粗糙度、密度、粘度、流量和泵扬程可复用；但波速、管材弹性、阀门关闭时间、泵启停事件没有字段，只能做“事件参数由页面临时输入”的演示版 |
| 泄漏检测/负压波定位 | 不兼容 | 需要首末站压力/流量时间序列、传感器位置、采样时间戳和报警基线，当前数据管理没有这些数据 |
| 多油品排产/混油界面 | 不兼容 | 需要批次、库存、需求、交付时窗、注入/卸油计划和多产品序列，当前油品表只有密度和粘度 |
| 含蜡原油沉积/再启动 | 不兼容 | 需要温度、WAT、蜡含量、环境温度、保温层和沉积参数 |

因此，泄漏定位、多油品排产和含蜡沉积不能直接宣称为“基于当前项目真实数据”的计算。除非另外接入 CSV/传感器/调度数据，否则只能作为展示型扩展，不适合直接作为项目正式结果。

## 基于现有字段重新设计的竞赛路线

为了不改数据管理，又让计算逻辑明显区别于大创版，建议把页面改成：

### 1. 管道输送能力边界与瓶颈诊断

不是给一个流量算一个末站压力，而是反求在压力上下限和泵站能力下的：

- 最大安全输量；
- 最小经济输量；
- 压力瓶颈位置；
- 管道利用率；
- 各参数对应的可行运行域。

新增计算思路：对流量 `Q` 做区间搜索，寻找满足

```text
H_min ≤ H_end(Q) ≤ H_max
Q ≤ Q_pump_capacity
```

的最大可行流量和经济运行区间。它是“反求边界/能力评估”，不是原来的单点稳态分析。

### 2. 输送工况诊断与安全评分

不是改变一个参数再看摩阻，而是把现有字段形成一个运行状态向量：

```text
X = {流速、雷诺数、摩阻、压力裕度、泵负荷、单位能耗、管道利用率}
```

输出：

- 正常/关注/危险工况；
- 水力瓶颈解释；
- 能耗异常解释；
- 压力不足或过高的原因；
- 面向操作员的调整建议。

评分可采用归一化多指标模型：

```text
Risk = w₁·pressureRisk
     + w₂·velocityRisk
     + w₃·energyRisk
     + w₄·capacityRisk
```

它与原敏感性分析的差异在于：不再输出变量排序，而是输出一个工况诊断结论和原因链。

### 3. 泵—管系统运行点匹配与能耗/碳排评估

不是枚举 ZMI480/ZMI375 数量找“末站压力最小”，而是计算泵特性和管道系统特性的交点：

```text
H_pump(Q) = H_system(Q)
```

泵站已有额定扬程和排量，可以在页面上使用额定点构造可解释的简化泵曲线；正式版本应在泵站数据中补充真实曲线点，但不需要改变现有项目、管道和油品表。

系统曲线可以写为：

```text
H_system(Q) = Δz + h_f(Q) + H_required
```

输出：

- 实际运行点流量；
- 泵组工作区间；
- 泵效率和电机效率；
- 单位输量能耗；
- 年能耗和电费；
- 可选电力排放因子下的碳排估算；
- 偏离设计点的程度。

这和当前的固定组合枚举属于不同问题：当前是“选哪组泵”，竞赛版是“系统最终在哪个运行点工作，以及这个运行点是否经济”。

## 最稳妥的选择

如果数据管理必须完全不动，推荐采用：

```text
管道输送能力边界与瓶颈诊断
+ 输送工况诊断与安全评分
+ 泵—管系统运行点匹配与能耗评估
```

如果允许页面额外上传一次 CSV，但不改数据库表，则可以把第二项升级为泄漏检测；如果允许增加批次、库存和需求数据，才考虑多油品排产。

这个版本不能声称“只靠换界面就和大创 50% 不同”，但它能在以下层面形成可审查差异：

- 研究问题不同：单点计算 → 边界反求、状态诊断、运行点匹配；
- 输出不同：压力/摩阻 → 能力区间、瓶颈解释、经济运行点；
- 计算过程不同：正向代入 → 区间搜索、指标融合、曲线交点求解；
- 页面交互不同：填参数 → 拖动运行区间、点击瓶颈、切换运行策略。

## 当前决策

在用户确认前，不把泄漏定位、多油品排产或含蜡沉积写入现有项目正式后端；它们只保留为需要额外数据的备选方向。
